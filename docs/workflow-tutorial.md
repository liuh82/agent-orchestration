## 1. 快速开始

### 创建工作流
1. 进入 **工作流** 菜单
2. 点击 **新建工作流**
3. 输入名称（如"代码审查流程"）
4. 进入编辑器画布

### 基本操作
| 操作 | 方式 |
|------|------|
| 添加节点 | 从左侧面板拖拽到画布 |
| 连线 | 从节点底部圆点拖到另一个节点顶部圆点 |
| 配置节点 | 点击节点 → 右侧面板编辑 |
| 删除节点 | 选中节点 → 按 Delete 键或点击面板中的删除按钮 |
| 删除连线 | 选中连线 → Delete 键 |
| 保存 | 点击右上角 **保存** 按钮 |
| 运行 | 点击右上角 **运行** 按钮 |

## 2. 节点类型总览

### 🔵 触发器（工作流起点，无输入端口）

| 节点 | 功能 | 配置 |
|------|------|------|
| **手动触发** | 手动点击启动 | 无需配置 |
| **定时触发** | Cron 表达式定时执行 | Cron表达式、时区 |
| **Webhook触发** | 接收外部 HTTP 请求 | 请求方法、路径 |
| **输入** | 从项目/任务提取上下文 | 数据来源、提取字段 |

### 🟣 逻辑控制

| 节点 | 功能 | 输出端口 |
|------|------|---------|
| **IF** | 条件分支 | `true` / `false` |
| **Switch** | 多条件路由 | `case_0` / `case_1` / ... / `default` |
| **Loop** | 循环执行 | `body` / `done` |
| **Wait** | 等待/延迟 | 1个输出 |
| **Fork** | 并行分发 | `branch_0` / `branch_1`（最多2个） |
| **Join** | 并行汇合 | 1个输出 |

### 🔵 Agent

| 节点 | 功能 |
|------|------|
| **Agent** | 调用 AI Agent 执行任务（代码审查、翻译、总结等） |

### 🟣 工作流

| 节点 | 功能 |
|------|------|
| **子工作流** | 嵌套调用另一个工作流 |

### 🟢 数据

| 节点 | 功能 |
|------|------|
| **HTTP请求** | 调用外部 API |
| **Code** | 执行 Python/JavaScript 代码 |
| **Transform** | 数据格式转换 |

### 🔴 输出（工作流终点）

| 节点 | 功能 |
|------|------|
| **输出** | 格式化并输出最终结果 |
| **上下文输出** | 写回任务的上下文字段（摘要、备注等） |
| **结果输出** | 标记工作流完成，更新任务状态 |

## 3. 连线规则

### 连线类型（自动识别）
连线会根据**源节点类型**自动设置样式：

| 源节点 | 连线样式 | 说明 |
|--------|---------|------|
| IF / Switch | 🟢绿色虚线 / 🔴红色虚线 | 条件分支 |
| Fork / Join / Parallel | 🔵蓝色实线 | 并行分支 |
| 其他节点 | ⚪灰色实线 | 普通流转 |

### 连线规则
- ✅ 同一个输出端口可以连多个目标节点
- ✅ 多个输出端口可以连同一个目标节点（如 Join 的多个输入）
- ❌ 不能自连（节点连自己）
- ❌ 不能形成循环（除 Loop 节点外）

## 4. 节点配置详解

### 4.1 Agent 节点

**基础配置：**
- **模型**：选择 AI 模型
- **Prompt**：给 Agent 的指令
- **温度**：创造性程度（0-1）
- **最大Token**：输出长度限制

**高级设置**（点击展开）：
- **超时时间**：Agent 执行超时（秒），默认180
- **失败策略**：
  - `停止` — Agent 失败则整个工作流停止
  - `跳过` — 跳过此节点，继续下游
  - `重试` — 自动重试
  - `使用回退值` — 用预设值代替失败结果
- **回退值**：失败时使用的替代文本（仅 fallback 策略时显示）
- **输出过滤**：指定只保留哪些输出字段（JSON数组格式）
- **启用缓存**：相同输入时复用之前的输出

### 4.2 Fork 节点

- **分发模式**：
  - `广播` — 所有分支收到相同的上游数据
  - `分发` — 每个分支收到不同的数据（需要配置 branchData）
- **分支数量**：当前支持 2 个分支

### 4.3 Join 节点

- **等待模式**：
  - `等待全部` — 所有上游分支都完成后才继续
  - `任意一个` — 任一分支完成即可继续
- **合并策略**：
  - `追加` — 保留每个分支的独立结果，额外生成 `merged` 数组
  - `合并` — 深度合并所有分支输出到一个对象
- **超时时间**：等待分支完成的超时（秒）

### 4.4 Input 节点

- **数据来源**：
  - `项目` — 从关联项目中提取数据
  - `任务` — 从关联任务中提取数据
  - `手动` — 直接使用输入数据
  - `上游` — 使用上游节点的输出
- **提取字段**：按需选择要提取的字段（如标题、描述、文件）
- **包含文件**：是否包含附件文件内容
- **组装模板**：用 `{{ field }}` 引用字段组装文本

### 4.5 Code 节点

- **语言**：Python / JavaScript
- **代码**：要执行的代码
- 可用变量：`upstream`（上游输出）、`input`（输入数据）
- 输出方式：`print()` 输出的 JSON 会被解析为节点输出

### 4.6 上下文输出 / 结果输出

**上下文输出**：将中间结果写回任务
- **输出目标**：可添加多条，每条指定写入字段
  - `summary` — 摘要
  - `notes` — 备注
  - `tags` — 标签
- **追加模式**：追加到已有内容 / 覆盖

**结果输出**：标记工作流结束
- **输出格式**：JSON / Markdown / 纯文本
- **完成后动作**：标记完成 / 标记完成并通知 / 不操作

## 5. 示例工作流

### 示例1：最简单的 Agent 工作流

```
手动触发 → Agent → 输出
```

1. 拖入 **手动触发**
2. 拖入 **Agent**，配置 Prompt："请帮我审查以下代码"
3. 拖入 **输出**，格式选 Markdown
4. 连线：触发 → Agent → 输出
5. 保存并运行

### 示例2：条件分支

```
手动触发 → Agent(分类) → IF → Agent(正面回复) → 输出
                              → Agent(负面回复) → 输出
```

1. 拖入 **手动触发**、**Agent(分类)**、**IF**、两个 **Agent**、两个 **输出**
2. IF 配置条件字段为分类 Agent 的输出
3. 从 IF 的 `true` 端口连到正面回复 Agent
4. 从 IF 的 `false` 端口连到负面回复 Agent

### 示例3：并行执行（Fork/Join）

```
手动触发 → Fork → Agent(A:前端审查) ─┐
                      Agent(B:后端审查) ─┤→ Join → 输出
```

1. 拖入 **手动触发**、**Fork**、两个 **Agent**、**Join**、**输出**
2. Fork 配置：广播模式
3. Agent A Prompt："审查前端代码"
4. Agent B Prompt："审查后端代码"
5. Fork `branch_0` → Agent A，Fork `branch_1` → Agent B
6. Agent A → Join，Agent B → Join（两条线都连到 Join 的输入端口）
7. Join → 输出
8. Join 配置：等待全部 + 追加合并

### 示例4：代码审查完整流程

```
输入(项目数据) → Agent(审查) → IF(严重程度) → 结果输出(标记完成)
                                   → 上下文输出(记录问题) → 结果输出
```

1. **输入**：数据来源=项目，提取字段=标题、描述、文件
2. **Agent(审查)**：Prompt 使用 `{{ input.title }}` 引用项目信息
3. **IF**：根据 Agent 输出的严重程度分支
4. 高严重度 → **结果输出**（标记任务为需处理）
5. 低严重度 → **上下文输出**（写入备注）→ **结果输出**（标记完成）

## 6. 常见问题

### Q: 为什么 Fork 只有 2 个分支？
当前版本 Fork 节点固定提供 2 个分支（branch_0 和 branch_1）。后续版本将支持动态增减分支数量。

### Q: Agent 节点执行失败怎么办？
在 Agent 节点的**高级设置**中，将失败策略改为"跳过"或"重试"，避免整个工作流因单个节点失败而中断。

### Q: 如何在工作流中引用上游节点的输出？
在 Agent 的 Prompt 或 Code 节点的代码中，使用 `{{ node_id.output.field }}` 语法。例如上游 Agent 节点 ID 为 `review_1`，则写 `{{ review_1.output.summary }}`。

### Q: 连线为什么连不上？
- 确认两个节点都有正确的端口（顶部=输入，底部=输出）
- 触发器类节点（手动触发、定时触发、Webhook、输入）没有输入端口
- 从输出端口（节点底部）拖向输入端口（节点顶部）

### Q: 工作流执行超时？
- Agent 节点的超时时间在高级设置中调整
- Code 节点的超时时间在配置面板中设置
- Join 节点可以设置等待超时
