## 任务目标
实现基于工作流模板创建项目/任务的完整实例化机制。

## 具体要求

### 10.1 创建流程
1. 用户点击「创建」→ 选择工作流模板
2. 弹出选择：创建项目（多任务）还是创建任务（单任务）
3. 填写基本信息：名称、描述
4. 配置覆盖（可选）：修改工作流节点的可覆盖配置项
5. 选择执行方式：立即执行 / 定时（cron）/ 循环（interval）
6. 创建成功后进入项目/任务详情页

### 10.2 项目/任务合并
- 项目中心增加创建入口
- 创建时支持选择"项目"或"任务"
- 项目详情页内可以创建子任务（基于同一工作流或其他工作流）
- 取消独立的任务中心页面，任务列表整合到项目内
- 支持独立任务（不归属项目）也在项目列表中展示

### 10.3 配置覆盖机制
- 工作流节点标记了 `config_override_schema` 的字段
- 创建任务时可以修改这些字段的值
- 未修改的字段使用工作流模板的默认值
- 配置保存到 task_agent_configs 表

### 10.4 文档隔离
- 每个任务实例有独立的文档库
- 上传/关联的文档只在该任务内可见
- 工作流模板可以定义文档模板（预置文档结构）

### 10.5 定时/循环执行
- 创建任务时可选择执行方式
- 立即执行：创建后立即开始执行工作流
- 定时执行：配置 cron 表达式，到时间自动执行
- 循环执行：配置间隔（如每小时、每天），自动循环
- 执行记录：每次执行产生独立的 workflow_execution 记录

### 10.6 项目概述页完善
- 项目描述长文字：截断 + 展开/收起
- 显示创建者
- 展示项目全貌：任务数/状态、文档数、关联工作流、执行历史
