# Nexus 开发任务 T9：工作流执行引擎升级

## 必读文件（先读完再动手）
- CLAUDE.md
- docs/architecture-v3.md（工作流引擎部分）
- backend/app/services/ 目录下 workflow 相关文件
- backend/app/routers/workflows.py

## 任务目标
升级工作流执行引擎，支持分支逻辑和子工作流调用。

## 具体要求

### 9.1 分支节点执行
- IF 节点：评估条件表达式，选择 true/false 输出
  - 支持的比较：等于、不等于、大于、小于、包含、正则匹配
  - 条件来源：上游节点输出、任务变量、环境变量
- Switch 节点：按顺序评估多个条件，匹配第一个命中的分支
- 默认分支：所有条件都不匹配时走 default 输出

### 9.2 循环节点执行
- 固定次数循环：配置循环次数，每次循环设置 current_index 变量
- 列表遍历：遍历输入列表，设置 current_item 和 current_index
- 终止条件：支持 break 条件表达式
- 最大循环次数限制（防止无限循环，默认100）

### 9.3 子工作流调用
- 子工作流节点：加载目标工作流定义
- 参数传递：父工作流的输出作为子工作流的输入变量
- 执行等待：父工作流等待子工作流完成
- 输出合并：子工作流的输出合并到父工作流的变量上下文
- 防止无限递归：最大嵌套深度限制（默认5）

### 9.4 变量系统
- 节点间数据传递：`{{ node_id.output.field_name }}`
- 任务变量：`{{ task.variables.xxx }}`
- 环境变量：`{{ env.xxx }}`
- 上下文变量：`{{ context.user_id }}`, `{{ context.task_id }}`

### 9.5 错误处理
- 节点级重试：配置重试次数和间隔
- 节点级错误策略：停止/跳过/走错误输出
- 工作流级错误策略：停止所有/继续后续节点/通知管理员
