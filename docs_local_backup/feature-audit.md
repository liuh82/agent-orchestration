# Agent Orchestration 编排系统 — 功能梳理（完整版）

## 一、当前系统概览

**版本**: v2.4.0 | **技术栈**: React+Vite(前端) + FastAPI+SQLite(后端) + WebSocket(Bridge通信)

### 核心架构
```
前端 Dashboard ←→ FastAPI Backend ←→ Bridge Manager ←→ Remote Agent Bridges (WebSocket)
```

---

## 二、现有 9 个模块功能清单

---

### 1. Dashboard（总览页）

**路由**: `/` | **后端**: 无专用 API | **前端**: `Dashboard.tsx`

| 项目 | 状态 |
|------|------|
| 页面存在 | ✅ |
| 实时系统状态概览 | ❌ |
| 关键指标卡片 | ❌ |
| 最近活动/事件流 | ❌ |
| 图表可视化 | ❌ |

**功能作用与意义：**
Dashboard 是系统的「门面」和「指挥中枢入口」。用户打开系统的第一眼，应该能看到：多少 Agent 在线、多少任务在跑、成功率多少、今天花了多少钱、最近发生了什么事件。

**意义**：没有好 Dashboard，用户每次都要逐个页面翻找信息，效率极低。这是判断系统「好用」还是「难用」的第一印象。

### 2. Agent 管理（代理中心）

**路由**: `/agents` | **后端**: `/api/agents` (CRUD) | **前端**: `Agents.tsx`

| 功能 | 状态 |
|------|------|
| Agent 列表展示 | ✅ |
| 创建/编辑/删除 Agent | ✅ |
| Agent 日志查看 | ✅ |
| Agent 实时在线/离线状态 | ❌ |
| Agent 能力配置界面 | ❌ |
| Agent 健康检查/心跳监控 | ❌ |
| 批量操作 | ❌ |

**功能作用与意义：**
Agent 是编排系统中最核心的资源。管理页面需要让用户清楚知道：每个 Agent 是什么类型、用什么模型、当前在线还是离线、执行了多少任务、成功/失败率、响应速度如何。

**意义**：Agent 管理是日常操作最频繁的页面之一。实时状态指示器和能力配置直接决定了用户能不能高效管理和调度 Agent 团队。

### 3. Task 管理（任务中心）

**路由**: `/tasks` | **后端**: `/api/tasks` (CRUD) | **前端**: `Tasks.tsx`

| 功能 | 状态 |
|------|------|
| 任务列表（分页/过滤/搜索） | ✅ |
| 创建任务 | ✅ |
| 任务详情（状态/分配/日志） | ✅ |
| 任务状态流转 | ✅ |
| 输入文件上传/参数配置 | ❌ |
| 任务依赖关系管理 | ❌ |
| 任务重试机制（前端） | ❌ |
| 任务执行时间线/进度展示 | ❌ |
| 任务优先级调度 | ❌ |

**功能作用与意义：**
任务是编排系统的核心业务单元。用户需要：提交任务 → 分配给 Agent → 跟踪执行进度 → 查看结果 → 失败重试。

**意义**：任务管理直接决定用户的工作效率。缺少依赖管理意味着复杂任务只能手动串行；缺少重试机制意味着失败要手动重来；缺少时间线意味着不知道任务卡在哪里。

### 4. Workflow（工作流）

**路由**: `/workflows` | **后端**: `/api/workflows` | **前端**: `Workflows.tsx`

| 功能 | 状态 |
|------|------|
| 工作流列表 | ✅ |
| 工作流模板 | ✅ |
| 工作流执行 | ✅ |
| 可视化流程编排（拖拽连线） | ❌ |
| 条件分支/循环/并行执行 | ❌ |
| 人工审批节点 | ❌ |
| 超时处理/错误恢复 | ❌ |
| 工作流执行状态展示 | ❌ |

**功能作用与意义：**
工作流是编排系统最核心的能力 — 将多个 Agent、多个任务按照一定规则串联或并联起来，自动执行复杂业务流程。

**意义**：当前工作流引擎只是个骨架。没有可视化编排，用户只能写代码定义流程；没有条件分支和并行，流程只能是最简单的串行；没有审批节点，流程无法在人机协作中暂停等待决策。这是从「工具」到「平台」的关键跨越。

### 5. Organization（组织架构）

**路由**: `/org` | **后端**: `/api/org` | **前端**: `Org.tsx`

| 功能 | 状态 |
|------|------|
| 部门树形结构 | ✅ |
| 成员管理 | ✅ |
| 角色权限 | ✅ |
| 组织架构可视化（树形图） | ❌ |
| 角色权限与 Agent/任务的实际绑定 | ❌ |
| 权限矩阵视图 | ❌ |

**功能作用与意义：**
组织架构定义了「谁可以做什么」。在多人协作场景下，不同角色（管理员、开发者、观察者）应有不同的操作权限。

**意义**：当前角色权限只是数据层面存在，没有实际生效。这意味着任何人都能做任何操作。在团队使用场景下，权限控制是安全和秩序的基石。

### 7. Approvals（审批）

**路由**: `/approvals` | **后端**: 嵌在 org | **前端**: `Approvals.tsx`

| 功能 | 状态 |
|------|------|
| 审批列表 | ✅ |
| 审批历史 | ✅ |
| 审批与工作流节点的联动 | ❌ |
| 审批通知（实时推送） | ❌ |
| 审批操作流程完整闭环 | ❌ |

**功能作用与意义：**
审批是「人在回路中」的关键机制。某些敏感操作（部署上线、资金支出、数据删除）需要在执行前人工确认。

**意义**：审批系统如果与工作流脱节，就只能做独立的事后记录，无法在流程中实现「暂停→审批→继续」的协作模式。

### 9. Heartbeats（心跳/定时任务）

**路由**: `/heartbeats` | **后端**: `/api/heartbeats` | **前端**: `Heartbeats.tsx`

| 功能 | 状态 |
|------|------|
| 心跳任务列表 | ✅ |
| 创建/管理心跳 | ✅ |
| APScheduler 调度 | ✅ |
| 执行历史展示 | ❌ |
| 执行失败告警 | ❌ |
| 可视化调度日历 | ❌ |

**功能作用与意义：**
心跳/定时任务是自动化运维的基础。比如：每隔 5 分钟检查一次 Agent 健康状态、每天凌晨自动清理过期数据、每小时汇总一次成本数据。

**意义**：没有失败告警，定时任务挂了用户都不知道。没有执行历史，无法判断任务是否正常运行。这是系统「自运维」能力的基础。

## 三、Gateway 核心（Bridge 通信层）

**后端**: `/api/gateway` + WebSocket `/api/v1/gateway/ws` | **无前端页面**

| 功能 | 状态 |
|------|------|
| Bridge 注册/注销（WebSocket） | ✅ |
| 任务提交与路由 | ✅ |
| 任务状态更新（WS 推送） | ✅ |
| Bridge 列表查看 | ✅ |
| 强制断开 Bridge | ✅ |
| Rate Limiting | ✅ |
| 连接数限制 | ✅ |
| **前端管理页面** | ❌ |
| Bridge 连接状态实时监控 | ❌ |
| 任务路由策略配置 | ❌ |
| 消息协议可视化调试 | ❌ |

**功能作用与意义：**
Gateway 是整个编排系统的通信中枢 — 所有 Agent Bridge 通过 WebSocket 连接到 Gateway，任务通过 Gateway 分发给合适的 Bridge，执行结果通过 Gateway 回传。

**意义**：这是系统最核心的组件，却完全没有前端界面。用户无法看到：哪些 Bridge 在线、每个 Bridge 正在执行什么任务、消息是怎么流转的、出了问题怎么排查。没有监控，等于盲飞。这是第一优先要做的功能。

## 四、关键问题总结

| 类别 | 问题 | 严重度 | 为什么重要 |
|------|------|--------|-----------|
| **功能缺失** | Gateway 无前端管理页面 | 🔴 高 | 核心通信层不可见，无法监控和调试 |
| **功能缺失** | 工作流引擎不完善 | 🔴 高 | 编排系统的核心能力，目前只是骨架 |
| **功能缺失** | 任务依赖和重试机制 | 🟡 中 | 复杂任务无法自动化串行，失败要手动重来 |
| **实时性** | Agent 状态非实时推送 | 🟡 中 | 不知道 Agent 真实在线状态，任务可能分配给离线 Agent |
| **交互** | Dashboard 信息量不足 | 🟡 中 | 缺少全局视角，效率低 |
| **体验** | 前端 UI 整体粗糙 | 🟡 中 | 影响使用体验和信心 |
| **完整性** | 审批与工作流未联动 | 🟡 中 | 无法实现人机协作流程 |
| **完整性** | 组织架构权限未实际生效 | 🟢 低 | 多人协作时的安全基础，但可后补 |

## 五、建议迭代优先级

### 第一轮（核心骨架）— 让系统能看、能控

| 序号 | 功能 | 为什么优先 |
|------|------|-----------|
| 1 | **Gateway 监控页** | 核心通信层从不可见变为可见，否则排障全靠猜 |
| 2 | **Dashboard 重做** | 系统入口页，决定第一印象和使用效率 |
| 3 | **Agent 实时状态** | Agent 在线/离线实时感知，任务分配才能准确 |

### 第二轮（任务引擎）— 让系统能编排、能自动

| 序号 | 功能 | 为什么优先 |
|------|------|-----------|
| 4 | **任务流增强** | 依赖关系 + 重试 + 时间线，复杂任务才跑得起来 |
| 5 | **工作流引擎** | 可视化编排 + 条件分支 + 审批节点，从工具变平台 |

### 第三轮（管理与体验）— 让系统能多人用、好看

| 序号 | 功能 | 为什么优先 |
|------|------|-----------|
| 6 | **组织权限落地** | 多人协作的安全基础 |
| 7 | **前端 UI 统一重做** | 设计语言统一，交互体验提升 |
